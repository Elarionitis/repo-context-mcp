# Eval guidance

## What to test

Questions about public GitHub repositories that are not checked out locally:
overview and tech stack, run and test commands, folder layout, where code lives,
maintenance status, comparisons between repos, and reading specific files.

Good answers cite real file paths and dates from the repository instead of
guessing from memory. Some cases ask for exact details (a line number, the
files in a folder, workflow file names) that are hard to get right from memory
or from rendered web pages.

## What should not trigger

General coding questions with no GitHub repository involved, and questions
about the code already in the local workspace.

## Notes for graders

Facts like star counts, dates and release versions change over time. Grade on
whether the agent looked them up and reported them, not on exact numbers.
Line numbers and folder contents can also shift as the repositories change;
accept answers that match the repository at the time of the run.
